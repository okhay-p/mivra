# ADR-012: Model picker: one app-wide model and effort, chosen in the UI

**Context:** The model and reasoning effort come from `MIVRA_MODEL` and `MIVRA_REASONING_EFFORT` and are fixed when the server starts. The effort is set on the OpenRouter provider itself, so every call shares it. Switching models means editing `.env` and restarting. The provider registry (`packages/server/src/model.ts`) already resolves `anthropic`, `openai` and `openrouter` ids. Runs don't record which model produced them, yet the turn runner replays each step's provider metadata (such as reasoning signatures) on later turns. After a switch, that metadata would go to a model that never produced it, and some providers reject it.

**Options:** (A) keep env-only configuration; (B) one app-wide selection changed from the UI; (C) a selection per session; (D) a model per job (chat, syllabus, lessons).

**Decision:** (B). (D) is a later improvement; (C) is not planned.

- **One selection.** A `settings` table (key → JSON) holds the current `{ model, effort }`. Chat turns, syllabus generation and lesson generation all use it. There are no model env vars: `MIVRA_MODEL` and `MIVRA_REASONING_EFFORT` are retired (the server warns if they're set), so setup needs only `OPENROUTER_API_KEY` and nobody has to know a model id. Until the learner picks, a built-in default applies: GPT-6 Luna through OpenRouter at high effort. `PUT /api/settings/model` validates the model against the catalog and the effort against the levels that model supports.
- **Effort per call.** Effort moves from the provider's `extraBody` to each call's `providerOptions`, so changing it needs no restart. A change applies from the next run; a run already streaming keeps its model.
- **Runs record their model.** `runs` gains `model` and `effort`. On replay, provider metadata and signed reasoning are sent back only for replies from the same model; replies from another model replay as text.
- **Catalog.** `GET /api/models` serves OpenRouter's public model list (`/api/v1/models`) filtered to models whose `supported_parameters` include `tools`, since the learning tools need tool calling (batch variants are left out: they can't stream). Each entry carries id, name, context length, price and, when it supports `reasoning`, the effort levels it lists (`supported_efforts`) and its default. The server caches it in memory for about an hour and falls back to the last good copy when offline.
- **Picker.** A searchable picker in the composer (shadcn `popover` + `command`). Unsearched, it shows only Pinned (models the learner starred), Recent (the last 5 models used) and Suggested (about 8 tool-capable models shipped in server config, hidden once the learner has enough of their own; any that leave the catalog are dropped silently). Typing searches the whole catalog. `pinned` and `recent` live in `settings`; `recent` updates when a run starts. The effort control appears only for models that list effort levels, and offers Default plus those levels (from none, minimal, low, medium, high, xhigh and max); Default omits the parameter.
- **Provenance in the UI.** Each assistant reply shows the model that wrote it, from its run.

**Consequences:** Model choice becomes data rather than deployment config, and every reply can be traced to its model. Switching mid-session costs earlier replies' reasoning context. The catalog depends on OpenRouter being reachable at least once; tests and e2e inject a fixed catalog. Background generation can't use a cheaper model than chat until (D).

**Build order:**

1. OpenRouter: retire the model env vars for a built-in default, settings table, catalog endpoint, per-call effort, run provenance and the same-model replay rule, the picker, and the model label on replies.
2. Direct providers: the catalog groups by provider and lists only providers whose API key is set (OpenRouter, Anthropic, OpenAI). A per-provider mapping turns the effort level into each provider's option, such as Anthropic's thinking setting or OpenAI's `reasoningEffort`. As built: the AI SDK's `reasoning` call option does that mapping for Anthropic and OpenAI. Their model lists give only ids, so each direct model is described by (and listed only with) its OpenRouter counterpart, whose public list is loaded even without an OpenRouter key. The built-in default follows the keys: GPT-6 Luna through OpenRouter, else through OpenAI, else Claude Sonnet 5.5 through Anthropic.
3. Custom OpenAI-compatible providers (issue #69, owner-approved). A learner adds a provider under Settings → Model providers with a name, an API base URL, a key and model ids, and its models join the catalog under that provider. As built:
   - **Protocol:** Chat Completions only, through the AI SDK's OpenAI-compatible provider. Nothing infers Responses support or reasoning options from a model's name; the Responses API is deferred.
   - **Identity:** each provider gets a stable id when it's created, never reused even after it's removed, and its models are `custom:<provider id>/<model id>`. Renaming a provider changes no model's identity, the same model id on two providers (or on a built-in one) stays a separate model, and a removed provider's name is kept so its replies stay labelled.
   - **Catalog:** a custom model needs no OpenRouter counterpart. Its price is unknown and it offers no effort control (unconfirmed reasoning controls are omitted). A context length and output limit may be entered under Advanced; the output limit caps each call, and Mivra adds no other runtime budget of its own. Model ids come from `<base URL>/models` (with a Refresh models action) or are typed in by hand, which always works, including when the list fails. The picker shows each custom provider's models under its name without searching.
   - **Verification:** a model can be saved and selected untested; it shows "Not tested", "Works" or "Test failed". **Test model** makes a small streamed Chat Completions call that must call a tool and continue after the tool's result, and may spend a few tokens. Discovery and test results are separate, and both stop applying when the URL or key changes.
   - **Provenance and replay:** a custom model's run also records a fingerprint of the endpoint it called (`runs.endpoint`). Provider metadata and signed reasoning replay only to the same model at the same endpoint, so a changed URL never receives another destination's private reasoning. A run keeps the configuration it started with.
   - **Removal:** removing the selected provider, or the selected model from its provider, leaves the selection in place and the picker asks the learner to choose another model; runs fail with that message rather than being rerouted.
4. Later: sign-in with a ChatGPT subscription via OAuth. First confirm that OpenAI permits third-party apps to use subscription credentials; this needs its own ADR. Also later: a model per job (D).
